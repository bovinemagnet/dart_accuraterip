= `query`
:description: Raw AccurateRip database lookup from four hex/decimal arguments, with no audio required, using the dart-accuraterip query subcommand.
:keywords: dart-accuraterip, cli, query, lookup, database

Fetch and pretty-print the raw AccurateRip database response for a disc ID.
Unlike xref:verify.adoc[`verify`], `query` needs no audio at all — just the four numbers that identify a disc.

== Synopsis

[source,console,subs="attributes+"]
----
$ {cli-command} query <discId1-hex> <discId2-hex> <cddbId-hex> <trackCount>
----

All three disc IDs are parsed as hexadecimal, with or without a leading `0x`.
`trackCount` is parsed as a positive decimal integer.

== When to use it

`query` is a debugging tool, useful for:

* Sanity-checking a disc ID computed by another tool — rip the same disc with two tools, feed both sets of IDs through `query`, and compare.
* Inspecting the raw database response for a known disc without re-ripping it, including every pressing's confidence, primary CRC and `frame450Crc`.
* Understanding the xref:ROOT:wire-format.adoc[] response layout hands-on, since the printed output mirrors the parsed chunk structure field for field.

See also xref:ROOT:lookup.adoc[] for how the library builds the request URL and parses the response that `query` is printing.

== Sample session

[source,console,subs="attributes+"]
----
$ {cli-command} query 0000f21c 00027ef8 05021002 2
Querying: http://www.accuraterip.com/accuraterip/c/1/2/dBAR-002-0000f21c-00027ef8-05021002.bin

Track 01: 2 pressing(s)
  confidence= 12  crc=0x284fc705  frame450Crc=0x3b97f8a4
  confidence=  9  crc=0xdc77f9ab  frame450Crc=0x00000000
Track 02: 2 pressing(s)
  confidence= 20  crc=0x9cc1f32e  frame450Crc=0xdc5500de
  confidence=  9  crc=0xdd97d2c3  frame450Crc=0x00000000
----

For each track here, the two pressings hold the v1 and the v2 CRC of the same audio, submitted by different rippers — which is why xref:ROOT:wire-format.adoc[] says a client must try both.
Confidence values grow as more rips are submitted, so live output may show higher numbers than this.

Requests carry the header `User-Agent: dart-accuraterip/{cli-version}` so the database maintainers can see what is generating the traffic, and give up after a 10-second timeout.

If the disc isn't in the database, `query` prints `No entry in the AccurateRip database for this disc.` and exits `1`.
If the lookup itself fails (network error, timeout, an unexpected HTTP status or an unparseable response), `query` instead prints `dart-accuraterip query: database lookup failed: ...` to stderr and exits `69`.

== Exit codes

`0` on a successful lookup (even if some tracks have zero pressings listed).
`1` if the disc has no database entry at all.
`64` (`EX_USAGE`) if any disc ID doesn't fit in 32 bits or `trackCount` isn't a positive integer.
`69` (`EX_UNAVAILABLE`) if the database lookup fails, as distinct from the disc having no entry.
See xref:exit-codes.adoc[].
