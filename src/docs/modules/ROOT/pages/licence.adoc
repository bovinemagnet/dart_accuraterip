This section is a plain-language summary for a Dart or Flutter developer evaluating whether to depend on {project-name}.

GPL-3.0 is a *copyleft* licence.
If you distribute a modified version of this package's own source code, that modified version must also be licensed under GPL-3.0, and its source must be made available to whoever you distribute it to.

The part that matters most for application authors is how GPL-3.0 treats linking.
Dart and Flutter typically compile dependencies directly into the resulting application — there is no separate, dynamically-loaded library boundary the way a shared `.so` might provide.
Because of that, linking {project-name} into your application makes your application, as distributed, subject to the GPL's terms.

In practice this generally means: if you distribute an application that depends on {project-name} to others, that application should itself be released under a GPL-compatible licence.

This is a materially different, stronger obligation than a permissive licence such as MIT, BSD, or Apache-2.0 would impose.
Weigh this deliberately before adding {project-name} as a dependency of a proprietary or closed-source product.

TIP: If GPL-3.0's obligations do not suit your project, {project-name} is not the package for you — there is no dual-licensing option.
