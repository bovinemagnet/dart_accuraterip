== The complete program

Save this as `verify_rip.dart`, run `dart pub add dart_accuraterip http` in the same project, and run it with a list of WAV files in track order:

[source,console]
----
$ dart run verify_rip.dart track01.wav track02.wav track03.wav
----

[source,dart]
----
import 'dart:io';
import 'dart:typed_data';

import 'package:dart_accuraterip/dart_accuraterip.dart';
import 'package:http/http.dart' as http;

Future<void> main(List<String> args) async {
  if (args.isEmpty) {
    stderr.writeln('Usage: dart verify_rip.dart <track01.wav> [track02.wav ...]');
    exitCode = 64;
    return;
  }

  // Read every track's PCM up front, in the order the tracks appear
  // on the disc — both the disc ID and the first/last-track skip
  // window depend on getting this order right.
  final pcmTracks = <Uint8List>[];
  final frameCounts = <int>[];
  for (final path in args) {
    final wavBytes = File(path).readAsBytesSync();
    parseWavFormat(wavBytes).requireRedBookCdAudio();
    final pcm = extractPcmFromWav(wavBytes);
    pcmTracks.add(pcm);
    frameCounts.add(pcm.lengthInBytes ~/ 4); // 4 bytes per stereo frame
  }

  final discId = AccurateRipDiscId.fromTrackSampleCounts(frameCounts);
  print('Disc ID: discId1=0x${discId.discId1.toRadixString(16).padLeft(8, '0')} '
      'discId2=0x${discId.discId2.toRadixString(16).padLeft(8, '0')} '
      'trackCount=${discId.trackCount}');

  final client = AccurateRipClient(
    fetch: (uri) async {
      final response = await http.get(uri);
      if (response.statusCode == 404) return Uint8List(0);
      if (response.statusCode != 200) {
        throw http.ClientException('HTTP ${response.statusCode}', uri);
      }
      return response.bodyBytes;
    },
  );

  final result = await client.queryDisc(discId);
  if (result == null) {
    print('No entry in the AccurateRip database for this disc.');
    print('Either this exact disc has never been submitted, or the '
        'disc ID is wrong (check the track count and order).');
    return;
  }

  for (var i = 0; i < pcmTracks.length; i++) {
    final isFirst = i == 0;
    final isLast = i == pcmTracks.length - 1;

    final v1 = computeArV1(pcmTracks[i], isFirstTrack: isFirst, isLastTrack: isLast);
    final v2 = computeArV2(pcmTracks[i], isFirstTrack: isFirst, isLastTrack: isLast);

    final track = result.tracks.firstWhere(
      (t) => t.trackNumber == i + 1,
      orElse: () => AccurateRipTrackResult(trackNumber: i + 1, entries: const []),
    );

    if (track.entries.isEmpty) {
      print('Track ${i + 1}: no entries for this track in the response.');
      continue;
    }

    final matching = track.entries
        .where((e) => e.matches(computedV1: v1, computedV2: v2))
        .toList();

    if (matching.isEmpty) {
      print('Track ${i + 1}: NOT ACCURATE '
          '(v1=0x${v1.toRadixString(16).padLeft(8, '0')} '
          'v2=0x${v2.toRadixString(16).padLeft(8, '0')}, '
          'no match among ${track.entries.length} known pressing(s)).');
      continue;
    }

    final bestConfidence =
        matching.map((e) => e.confidence).reduce((a, b) => a > b ? a : b);
    print('Track ${i + 1}: accurate, confidence $bestConfidence '
        '(${matching.length} matching pressing(s)).');
  }
}
----

== Interpreting the result

A verification run lands in one of four buckets:

[cols="1,3"]
|===
| Outcome | What it means

| `result == null` — no entries at all
| Either this disc has never been submitted to AccurateRip, or the disc ID is wrong. Double-check the track order and that every track's frame count came from the full, untrimmed WAV — a missing or reordered track changes every offset from that point on (see xref:disc-id.adoc[]).

| Entries present, but no track matches
| The rip is not bit-accurate for the pressings on record, *or* this is a genuinely different pressing than any submitted so far, *or* the ripping drive has a read-offset problem that shifts every sample by a constant number of frames. A read-offset issue typically causes every track to mismatch at once, which is a useful diagnostic signal.

| Match, low confidence
| At least one submission agrees with your rip, but few people have submitted this exact pressing. Treat it as a decent signal, not a certainty.

| Match, high confidence
| Many independent submissions agree with your rip's checksum for this track. This is as close to "provably correct" as AccurateRip gets.
|===

[TIP]
====
`AccurateRipEntry.frame450Crc` is exposed on every entry but this recipe never reads it.
It is a secondary checksum over only the first 450 stereo frames of the track, used by tools like CUETools to detect a *constant* drive read-offset rather than a wrong rip — often `0` on older pressings that predate the field.
You don't need it for a plain "is my rip bit-accurate?" check; `AccurateRipEntry.matches` is sufficient.
====

== The zero-code alternative

If you don't want to write or maintain a Dart program at all, xref:cli:verify.adoc[the `verify` CLI command] runs exactly this recipe from the terminal, against a directory of WAV files, and exits non-zero on any mismatch — handy for scripting into a ripping pipeline.
